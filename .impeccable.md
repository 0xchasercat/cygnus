## Design Context

### Users

Cygnus is used by developers and self-hosting operators deploying Bun and Node applications from folders, the CLI, and GitHub. They need to move quickly from a working local repository to a reliable public or private deployment, diagnose failures without leaving the dashboard, and tune resources without becoming infrastructure specialists.

### Brand Personality

Calm, precise, capable. The interface should inspire confidence that consequential infrastructure changes are understandable and reversible, while retaining Cygnus's distinctive light technical instrument-panel character.

### Aesthetic Direction

Refined technical minimalism using the existing light visual system, typography, restrained blue accent, compact instrumentation, and generous whitespace. Advanced infrastructure controls use progressive disclosure. Avoid generic settings grids, decorative charts, glassmorphism, excessive cards, and security language that obscures product behavior.

### Design Principles

1. Working defaults first: integrated ingress remains the default and setup can be completed without understanding advanced networking.
2. Show the consequence beside the control: resource and ingress settings explain whether they require restart, redeploy, DNS, proxy, or firewall changes.
3. Never expose a condition without recovery: OOM risk has a memory control, changed environment has a redeploy action, and failed operations have visible reasons and retry paths.
4. Progressive disclosure without missing capability: advanced TCP and UDS controls appear only when selected, while all essential actions remain available on mobile and keyboard.
5. Prefer explicit, durable state over inference: dashboard, CLI, and node.json present the same validated configuration and endpoint model.
6. Meet WCAG AA contrast and interaction expectations, including visible focus, semantic errors, reduced-motion support, wrapping for long infrastructure values, and touch-friendly controls.
